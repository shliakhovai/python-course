# Домашнє завдання

## Технічне завдання: Робота з REST API через `requests`

## Мета

Попрактикуватися у роботі з REST API за допомогою бібліотеки `requests`:

- виконання GET, POST, PUT/PATCH, DELETE запитів;
- перевірка статусу відповіді через `raise_for_status()`;
- обробка помилок запиту (`try/except`);
- побудова простого термінального застосунку (`main()` з меню), яке керує користувачами через API.

> **Встановлення бібліотеки:**
>
> ```bash
> pip install requests
> ```

Для завдання використовуємо тестовий ресурс [jsonplaceholder.typicode.com](https://jsonplaceholder.typicode.com/) — фейковий REST API, який імітує CRUD-операції над користувачами (`/users`), але нічого насправді не зберігає на сервері. Це нормально: сервер завжди повертає "успішну" відповідь з тими даними, які ти надіслав (або тестовими даними), навіть якщо запис не збережеться.

## Основні завдання

## 1. Функції для роботи з `/users`

Створи такі функції-обгортки над запитами до `https://jsonplaceholder.typicode.com/users`. Кожна функція повинна:

- виконувати відповідний HTTP-запит через `requests`;
- викликати `response.raise_for_status()`, щоб отримати виняток при помилковому статусі (`4xx`/`5xx`);
- повертати **словник** такого вигляду:

```python
{
    "status_code": response.status_code,
    "data": response.json(),
}
```

### `get_users() -> dict`

`GET /users` — отримати список усіх користувачів.

### `get_user(user_id: int) -> dict`

`GET /users/{id}` — отримати одного користувача за `id`.

### `create_user(user_data: dict) -> dict`

`POST /users` — створити нового користувача. `user_data` передається як тіло запиту (`json=user_data`). Очікуваний статус — `201`.

### `modify_user(user_id: int, user_data: dict) -> dict`

`PATCH /users/{id}` — оновити дані користувача (можна оновити лише частину полів).

### `remove_user(user_id: int) -> dict`

`DELETE /users/{id}` — видалити користувача. Зверни увагу: тіло відповіді тут зазвичай порожнє (`{}`), тому `response.json()` поверне порожній словник — це нормально.

---

## 2. Обробка помилок

`raise_for_status()` кидає виняток `requests.exceptions.HTTPError`, якщо сервер повернув код `4xx`/`5xx` (наприклад, запит `get_user(9999)` до неіснуючого користувача поверне `404`).

У `main()` обгортай виклики функцій у `try/except`, лови щонайменше:

- `requests.exceptions.HTTPError` — помилковий статус-код;
- `requests.exceptions.RequestException` — загальніша помилка (немає з'єднання, таймаут тощо).

При помилці виводь зрозуміле повідомлення користувачу, а не трейсбек.

---

## 3. `main()` — термінальний застосунок

Реалізуй `main()`, яка показує меню в циклі й дає користувачу обрати дію:

```
1. Переглянути всіх користувачів
2. Переглянути користувача за ID
3. Створити користувача
4. Оновити користувача
5. Видалити користувача
0. Вийти
```

Вимоги:

- дані для `create_user` / `modify_user` (ім'я, email тощо) запитуються через `input()`;
- після кожного запиту виводиться і `status_code`, і сам результат (`data`) у читабельному вигляді;
- некоректний ввід (наприклад, текст замість номера пункту меню або не-число замість `id`) не має "ронити" програму;
- цикл триває, доки користувач не обере `0`.

## Приклад використання

```python
result = get_user(1)
print(result["status_code"])  # 200
print(result["data"]["name"])  # Leanne Graham

new_user = create_user({"name": "John Doe", "email": "john@example.com"})
print(new_user["status_code"])  # 201
```
