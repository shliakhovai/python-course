# Домашнє завдання

## Технічне завдання: CRUD API для користувачів на FastAPI

## Мета

Навчитися самостійно реалізовувати HTTP-ендпоінти на FastAPI та розуміти структуру кожного ендпоінта:

- оголошення маршруту (`@app.get`, `@app.post`, `@app.delete`);
- джерело вхідних даних: параметр шляху (path parameter), параметр запиту (query parameter) або тіло запиту (Pydantic-модель);
- значення, що повертається, та статус-код відповіді;
- сигналізація про помилку через `HTTPException` (наприклад, `404 Not Found`).

Дані користувачів зберігаються у списку в оперативній пам'яті (`users: list`). Використання бази даних не передбачене; після перезапуску сервера дані скидаються.

> **Встановлення бібліотек:**
>
> ```bash
> pip install fastapi uvicorn
> ```
>
> **Запуск сервера** (файл `main.py`, застосунок у змінній `app`):
>
> ```bash
> uvicorn main:app --reload
> ```

## Теоретичні відомості

### Структура ендпоінта

```python
@app.get("/users/{user_id}")   # HTTP-метод і шлях; {user_id} — змінний сегмент шляху
def get_user(user_id: int):    # аргумент з тим самим іменем — параметр шляху
    return {"id": user_id}     # повернуте значення серіалізується у JSON
```

### Джерела вхідних даних

| Джерело | Спосіб оголошення | Приклад запиту |
| --- | --- | --- |
| Параметр шляху (path parameter) | ім'я аргументу функції збігається зі змінним сегментом `{...}` у шляху | `GET /users/5` → `user_id = 5` |
| Параметр запиту (query parameter) | аргумент функції, відсутній у шляху; зазвичай має значення за замовчуванням | `GET /users?min_age=30` → `min_age = 30` |
| Тіло запиту (request body) | аргумент функції, тип якого — клас, успадкований від `BaseModel` | тіло `{"name": "John"}` → `body.name` |

### Статус-коди та помилки

- Успішна відповідь за замовчуванням має код `200`.
- Для створення ресурсу застосовується код `201`, який задається в декораторі: `@app.post("/users", status_code=201)`.
- За відсутності запитуваного ресурсу замість повернення `None` слід згенерувати виняток:
  `raise HTTPException(status_code=404, detail="User not found")`.

### Робота з Pydantic-моделлю

Перетворення екземпляра моделі на словник виконується методом `model.model_dump()`.

## Підготовка

У файлі `main.py` необхідно оголосити:

- застосунок `app = FastAPI()`;
- список `users` із 3–4 записами у форматі `{"id": ..., "name": ..., "email": ..., "age": ...}`;
- Pydantic-модель `UserCreate` з полями `name: str`, `email: str`, `age: int`.

Модель `UserCreate` описує вхідні дані запиту на створення: клієнт передає лише `name`, `email` та `age`, а `id` призначається на боці сервера.

## Завдання

Необхідно реалізувати чотири ендпоінти згідно з наведеними вимогами.

### 1. `GET /users`

- Параметри відсутні.
- Повертає повний список `users`.
- Статус-код `200`.

### 2. `GET /users/{user_id}`

- `user_id` — параметр шляху типу `int`.
- Повертає запис користувача з відповідним `id`.
- За відсутності такого користувача — `HTTPException` зі статус-кодом `404`.

### 3. `POST /users`

- Вхідні дані — тіло запиту типу `UserCreate`.
- Новий `id` обчислюється як збільшений на одиницю максимальний наявний `id` (для порожнього списку — `1`).
- Новий запис (`id` разом із полями моделі) додається до списку `users`.
- Повертає створений запис зі статус-кодом `201`.

### 4. `DELETE /users/{user_id}`

- `user_id` — параметр шляху типу `int`.
- За відсутності користувача — `HTTPException` зі статус-кодом `404`.
- За наявності — запис видаляється зі списку `users`; повертається повідомлення, наприклад `{"message": "User 2 deleted"}`.
